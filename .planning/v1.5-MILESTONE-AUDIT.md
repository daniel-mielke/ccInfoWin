## Post-UAT findings: WinUI3Localizer multi-segment UID quirk

UAT execution on 2026-05-18 surfaced an empty migration toast (test 25-1) that
traced back to a WinUI3Localizer 2.3.0 library quirk: keys split at the FIRST `.`
during dictionary build, causing multi-segment UIDs in both XAML `l:Uids.Uid` and
code-behind `GetLocalizedString()` to silently return empty strings.

**9 latent UI bugs uncovered** across phases that originally passed the SHIP audit
because their broken-rendering states were never visually verified (tests marked
PASS based on functional behavior only):
- Migration toast (25-1), PricingError InfoBar (27-4), OrgMismatch InfoBar (27-9)
- Settings → Konto Re-detect button (27-7), Sessions tab header/empty/orphan (26-7)
- Rename dialog title+buttons (26-1), NextWindow label (27-1)
- LastFetchRelative.* family — 5 strings (27-3)

**Additional architectural fix:** OrgPicker ContentDialog `ContainerContentChanging`
with Phase=0 + `e.Handled=true` rendered items as invisible clickable containers.
Replaced with declarative `DataTemplate` in `Page.Resources`.

**Permanent regression protection:** Two new scanners in `ResourceCoverageTests`:
- `XamlUidValues_AreSingleSegment_ForLocalizerLookup`
- `GetLocalizedStringCalls_UseSingleSegmentUids_ForLocalizerLookup`

Both run on every build and block any future multi-segment UID introduction.

Fix commits: `23f73c8` (UID renaming), `49890d2` (DataTemplate refactor),
`e5238dc` (protection tests).

**Lesson learned:** Functional UAT ≠ visual UAT. Future milestones should require
explicit text-content verification per localized string, not just "feature works."
