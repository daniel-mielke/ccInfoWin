**Status:** ✅ SHIPPED 2026-05-07
**Phases:** 20-23
**Total Plans:** 13 (10 base + 3 gap-closure)
**Source spec:** `spec/v1.11.1-macOS/spec-release-1.10.0-to-1.11.1.md`
**Audit:** `v1.4-MILESTONE-AUDIT.md` — PASSED, 21/23 fully verified, 2 deferred with full unit-test coverage

## Overview

Ported macOS v1.11.0 (polish & localization) and v1.11.1 (auth/session stability hotfix) features to Windows — robust sign-in/sign-out flow, history persistence that survives crashes and 5-hour resets, refresh spinner with anti-flicker minimum-display window, localized UI strings.

The four phases followed the spec's "Implementation Phases" ordering: high-risk auth stability first (foundation), then history hardening, UI polish, and localization gaps. Phase 20 was the only hard dependency — the remaining three phases each depended solely on Phase 20 and were independent of one another (history service vs. UI ViewModels vs. resw resource files — disjoint code paths).

Three gap-closure plans were inserted after UAT surfaced bugs: Plan 20-05 (cosmetic pill wrapper for the LoginView reload button), Plan 21-03 (Settings → Logout history-clearing — initially via WeakReferenceMessenger, then hotfixed to direct DI call after production GC issue), and Plan 22-04 (refresh-button IsEnabled belt-and-suspenders override).

## Milestone Summary

**Decimal Phases:** None — gap-closure plans were appended as additional waves within their parent phase (20-05, 21-03, 22-04) rather than inserted as decimal phases. This kept the requirement-to-phase mapping stable.

**Key Decisions:**

- D-01 (20-02): `_autoReauthAttempted` flag — single bool gates first-vs-second 401 routing; resets on AuthStateChanged success; testable via state-machine unit tests
- D-08 (21-02): Async cascade `PollUsageAsync → UpdateUsagePropertiesAsync → AppendHistoryPointAsync → SaveHistoryAsync` — no fire-and-forget, no `.Wait()`, no `async void`
- D-13 (21-02 / 21-03): Logout is the single source of truth for history clearing — direct DI call (after WeakReferenceMessenger pitfall in 21-03 hotfix)
- D-09 timer-type (22-03): `Microsoft.UI.Xaml.DispatcherTimer` wrapped behind `IDispatcherTimer` adapter — enables headless `FakeDispatcherTimer` unit tests
- D-04 belt-and-suspenders (22-04): Explicit `IsEnabled` x:Bind on `FooterRefreshButton` reinforces `[RelayCommand]` `CanExecute` in case binding-priority-order breaks the implicit chain
- D-01 keys-only-no-XAML (23-01): Codebase already uses `l:Uids.Uid` exclusively — RESEARCH grep verified L10N-02 trivially satisfied; no XAML migration needed

**Issues Resolved (3 production bugs caught by UAT):**

1. Phase 20 UAT Test 4 (cosmetic): Reload button glyph illegible against cream-white claude.ai login page — fixed by Plan 20-05 (Slate-900 pill wrapper, glyph foreground=White)
2. Phase 21 UAT Test 2 (major): Settings → Abmelden didn't clear `usage-history.json` (D-13 violation) — fixed by Plan 21-03, then hotfixed to direct call after WeakReferenceMessenger + AddTransient recipient-GC pitfall
3. Phase 22 UAT Test 1 (minor): Refresh button stayed clickable during refresh — fixed by Plan 22-04 (CanRefresh public + IsEnabled x:Bind)

**Issues Deferred to v1.5+:**

- AUTH-01/02 manual smoke (visual 401 trigger) — dev build can't easily force a 401; full unit-test coverage compensates
- POLISH-04 visual smoke — blocked by cold-start session-scanning bug (`backlog_session_dropdown_recent_sessions.md`)
- POLISH-07 visual smoke — blocked by pricing-service silent failure (`backlog_pricing_never_loaded.md`)
- Multi-account org-id picker — `TryMigrateOrgIdAsync` blindly takes `orgs[0]`, breaking dual-account users (`backlog_org_id_picker.md`)
- Next 5h-window start label feature request (`backlog_next_window_start_label.md`)

**Technical Debt Incurred:**

- WeakReferenceMessenger + AddTransient ViewModels = recipient-GC pitfall — architectural memory written for v1.5 review; pattern documented in `architecture_weakreferencemessenger_with_transient_vms.md`
- 2 pre-existing `ClaudeApiServiceTests` failures unchanged from v1.3 baseline — future cleanup item
