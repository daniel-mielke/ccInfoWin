    2. In `InitializeAsync()`, AFTER the existing `RefreshIntervalChangedMessage` registration (line 285-288), add the `SonnetContextChangedMessage` registration:
       ```csharp
       WeakReferenceMessenger.Default.Register<SonnetContextChangedMessage>(this, (r, m) =>
       {
           var vm = (MainViewModel)r;
           vm._dispatcherQueue?.TryEnqueue(() =>
           {
               if (vm.SelectedSession != null)
                   vm.UpdateSessionData(vm.SelectedSession.Session);
           });
       });
       ```

       CRITICAL design decisions:
       - Wraps `UpdateSessionData` in `_dispatcherQueue?.TryEnqueue()` because it modifies `[ObservableProperty]` fields (ContextUtilization, ContextPercentage, etc.) which must be set on the UI thread. See RESEARCH.md Pitfall 1.
       - Guards with `vm.SelectedSession != null` — if no session is selected, there is nothing to refresh.
       - Does NOT use `m.Value` (the new context size) — `UpdateSessionData` calls `_jsonlService.GetContextWindow()` which internally reads the saved setting from `ISettingsService`. The message is just a trigger.
       - Calls `UpdateSessionData(vm.SelectedSession.Session)` which is the same method called on normal data refresh, ensuring consistency.
  </action>
