Implement the JsonlService that owns the FileSystemWatcher, parses JSONL files, maintains the session index, and exposes context window + token data.

Purpose: This is the core data pipeline — it reads Claude Code's local JSONL transcript files, builds an in-memory session index, calculates context window utilization and token aggregations, caches results for instant startup, and uses a FileSystemWatcher for live updates. Plan 03 binds the UI directly to this service's data.

  <name>Task 1: Implement JsonlService core — tail read, parsing, session discovery, context window, tokens, cache</name>

  <behavior>
    - ReadTailLines reads only the last ~1MB of a file, discarding the first partial line after seek
    - ReadTailLines opens files with FileShare.ReadWrite to avoid locking conflicts with Claude Code
    - ParseJsonlEntries tolerates malformed lines (skips them, no exceptions)
    - ParseJsonlEntries uses JsonlEntry.JsonSerializerOptions for tolerant deserialization
    - GetContextWindow returns the LAST non-sidechain assistant message's usage as context (not cumulative)
    - GetContextWindow includes subagent context from {sessionId}/subagents/agent-*.jsonl files
    - GetTokenSummary aggregates output_tokens across ALL non-sidechain assistant messages
    - GetTokenSummary deduplicates entries by uuid+requestId combination
    - DiscoverSessions scans all *.jsonl files under the projects directory and groups by sessionId
    - Session display name comes from the cwd field of the first entry in the session
    - Cache is loaded from jsonl-cache.json on startup, and saved after each scan
    - Incremental read starts from cached LastReadPosition, reads only new bytes
  </behavior>
  <action>
    Create `CCInfoWindows/CCInfoWindows/Services/JsonlService.cs` implementing `IJsonlService`:

    **Constructor**: Accept optional `string? projectsDirectoryOverride = null` for test isolation (same pattern as UsageHistoryService). Default to `Path.Combine(Environment.GetFolderPath(SpecialFolder.UserProfile), ".claude", "projects")`. Accept optional `string? cacheDirectoryOverride = null` defaulting to `%LOCALAPPDATA%\CCInfoWindows`.

    **Private fields**:
    - `_projectsDirectory` (string)
    - `_cacheDirectory` (string)
    - `_sessions` (List<SessionInfo>, backed by lock)
    - `_sessionData` (Dictionary<string, SessionData>) — internal per-session aggregation
    - `_filePositions` (Dictionary<string, FilePositionMarker>) — from cache
    - `_watcher` (FileSystemWatcher?)
    - `_debounceTimer` (System.Threading.Timer?)
    - `_debounceLock` (object)
    - `_isScanning` (bool)

    **Internal class `SessionData`**: Holds per-session: lastAssistantEntry (JsonlEntry for context window), totalInputTokens, totalOutputTokens, seenIds (HashSet<string> for dedup), cwd, modelName, lastActivity, subagentFiles (list of paths).

    **ReadTailLines(string filePath)**: Static method. Open with `FileMode.Open, FileAccess.Read, FileShare.ReadWrite`. Seek to `Math.Max(0, stream.Length - 1_048_576)`. If seeked past 0, discard first line (partial). Yield remaining non-empty lines.

    **ReadIncrementalLines(string filePath, long startPosition)**: Like ReadTailLines but seeks to startPosition. Returns (lines, newPosition).

    **ParseFile(string filePath, bool incremental)**: Read lines (tail or incremental), deserialize each to JsonlEntry via `JsonSerializer.Deserialize<JsonlEntry>` in try/catch (skip malformed). Group into session data. For context window: track ONLY the last `type == "assistant"` entry where `isSidechain == false`. For tokens: sum `output_tokens` of all `type == "assistant"` entries where `isSidechain == false`, deduplicating by `uuid + "|" + requestId`. Update FilePositionMarker.

    **DiscoverSessions()**: Enumerate `Directory.GetFiles(_projectsDirectory, "*.jsonl", SearchOption.AllDirectories)`. Skip files in `subagents` directories for main session discovery. Parse each file. Build SessionInfo list from aggregated SessionData. Sort by LastActivity descending.

    **GetSubagentFiles(string sessionId)**: For each project directory, look for `{sessionId}/subagents/agent-*.jsonl`. Parse each, create SubagentContextData from last assistant entry.

    **GetContextWindow(string sessionId)**: From `_sessionData[sessionId].lastAssistantEntry`, compute TotalTokens = `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`. MaxTokens from `ModelContextLimits.GetMaxContextTokens(model)`. Include subagent data.

    **GetTokenSummary(string sessionId)**: Return `new TokenSummary(_sessionData[sessionId].totalInputTokens, _sessionData[sessionId].totalOutputTokens)`.

    **Cache**: `LoadCache()` reads `jsonl-cache.json`. `SaveCache()` writes file positions + per-session token sums. On `InitializeAsync()`: load cache -> populate _sessionData from cache -> fire DataUpdated -> scan files incrementally -> update _sessionData -> fire DataUpdated again -> save cache.

    **InitializeAsync()**: Set `_isScanning = true`, load cache, discover sessions, set `_isScanning = false`, start watcher.

    **Stop()**: Dispose watcher and debounce timer.

    Implement `IDisposable` with `Stop()` in Dispose.

    **Tests** in `CCInfoWindows.Tests/Services/JsonlServiceTests.cs`:
    - Create temp directory with sample JSONL files
    - Test ReadTailLines with a file > 1MB (verify first partial line discarded)
    - Test ParseFile with valid JSONL returns correct session data
    - Test ParseFile with malformed lines skips them without exception
    - Test GetContextWindow returns LAST assistant message tokens (not sum)
    - Test GetTokenSummary sums output_tokens with deduplication
    - Test DiscoverSessions finds all sessions from multiple JSONL files
    - Test incremental read only processes new lines
    - Use constructor override for test directory isolation

  <name>Task 2: Add FileSystemWatcher with debounce and register in DI</name>
  <files>
    CCInfoWindows/CCInfoWindows/Services/JsonlService.cs,
    CCInfoWindows/CCInfoWindows/App.xaml.cs
  </files>
  <behavior>
    - FileSystemWatcher starts on InitializeAsync with IncludeSubdirectories=true and *.jsonl filter
    - Changed/Created events debounce at 300ms via System.Threading.Timer before processing
    - ProcessFileChangeAsync reads only incremental bytes from changed file
    - OnWatcherError disposes and re-creates watcher with cooldown to prevent infinite restart loops
    - IJsonlService is resolvable from DI as a singleton
  </behavior>
  <action>
    **Add watcher methods to JsonlService.cs** (extend the file created in Task 1):

    **StartWatching()**: Called at end of InitializeAsync. Create `FileSystemWatcher(_projectsDirectory)` with `Filter = "*.jsonl"`, `IncludeSubdirectories = true`, `NotifyFilter = NotifyFilters.LastWrite | NotifyFilters.FileName | NotifyFilters.Size`, `InternalBufferSize = 65536` (64KB to prevent overflow). Subscribe to `Changed` and `Created` events via `OnFileChanged`. Subscribe to `Error` event via `OnWatcherError`. Set `EnableRaisingEvents = true`. Guard: if `_projectsDirectory` doesn't exist, create it (Directory.CreateDirectory) before creating watcher.

    **OnFileChanged(object sender, FileSystemEventArgs e)**: Debounce with 300ms timer. Lock `_debounceLock`, dispose existing `_debounceTimer`, create new `System.Threading.Timer` with callback `_ => ProcessFileChangeAsync(e.FullPath)`, dueTime 300, period `Timeout.Infinite`.

    **ProcessFileChangeAsync(string filePath)**: Parse changed file incrementally (from cached position). Update `_sessionData` for affected session. Update `_sessions` list. Save cache. Raise `DataUpdated` event. All wrapped in try/catch — never let exceptions escape the timer callback.

    **OnWatcherError(object sender, ErrorEventArgs e)**: Log error (Debug.WriteLine for now). Dispose old watcher. Re-create watcher via StartWatching(). Guard against infinite restart loops with a cooldown counter.

    **DI registration in App.xaml.cs**: Add `services.AddSingleton<IJsonlService, JsonlService>();` in `ConfigureServices()`, after existing singleton registrations and before ViewModel registrations.

    **Note**: The watcher stays active for the entire app lifetime. Session switches in the UI do NOT restart the watcher — the watcher monitors ALL sessions simultaneously (per CONTEXT.md decision).
  </action>
