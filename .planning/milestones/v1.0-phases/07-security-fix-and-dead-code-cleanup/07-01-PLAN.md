**1. Add `Reset()` to `IWebViewBridge` interface** (`IWebViewBridge.cs`):

Add method signature after `FetchJsonAsync`:
```csharp
void Reset();
```

**2. Enhance `Reset()` in `WebViewBridge.cs`** to drain `_pending` TCS entries:

Replace the existing `Reset()` method body (starting at line 35) with:
```csharp
public void Reset()
{
    if (_coreWebView is not null)
    {
        _coreWebView.WebMessageReceived -= OnWebMessageReceived;
    }
    _coreWebView = null;
    _dispatcherQueue = null;

    foreach (var key in _pending.Keys)
    {
        if (_pending.TryRemove(key, out var tcs))
        {
            tcs.TrySetResult(null);
        }
    }
}
```

This prevents 30-second ghost hangs on logout from in-flight fetch requests.

**3. Inject `IWebViewBridge` into `MainViewModel` and call `Reset()` in `Logout()`**:

a) Add field at the top of MainViewModel (near other `private readonly` fields):

d) In `Logout()` method (line 782), add `_bridge.Reset()` call BEFORE `WeakReferenceMessenger.Default.Send(...)`:
```csharp
[RelayCommand]
private void Logout()
{
    _historyService.ClearHistory();
    _credentialService.ClearCredentials();
    _bridge.Reset();
    WeakReferenceMessenger.Default.Send(new AuthStateChangedMessage(false));
    IsSessionExpired = false;
    _navigationService.NavigateTo<LoginView>();
}
```

The Reset() must be called BEFORE the AuthStateChangedMessage because the message triggers navigation away from MainView. Calling Reset() first makes any in-flight FetchJsonAsync return null immediately.
