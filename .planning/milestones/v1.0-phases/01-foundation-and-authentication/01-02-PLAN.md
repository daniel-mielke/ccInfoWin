    1. Create Services/CredentialService.cs implementing ICredentialService:
       - Uses AdysTech.CredentialManager static API (pattern from 01-RESEARCH.md)
       - Credential target: "CCInfoWindows/claude-session"
       - SaveSessionToken: creates NetworkCredential("sessionKey", token), calls CredentialManager.SaveCredentials
       - GetSessionToken: calls CredentialManager.GetCredentials, returns Password or null
       - ClearCredentials: calls CredentialManager.RemoveCredentials, wraps in try/catch (credential may not exist)
       - No hardcoded tokens or secrets anywhere (SECU-01, SECU-02)

    2. Create Messages/AuthStateChangedMessage.cs:
       - Simple record/class implementing ValueChangedMessage&lt;bool&gt; from CommunityToolkit.Mvvm.Messaging.Messages
       - true = logged in, false = logged out
       - Used with WeakReferenceMessenger.Default.Send()
  </action>

<task type="auto">
  <name>Task 2: LoginView with WebView2 and LoginViewModel with cookie extraction</name>
  <files>
    CCInfoWindows/CCInfoWindows/Views/LoginView.xaml,
    CCInfoWindows/CCInfoWindows/Views/LoginView.xaml.cs,
    CCInfoWindows/CCInfoWindows/ViewModels/LoginViewModel.cs
  </files>
  <action>
    1. Create ViewModels/LoginViewModel.cs:
       - Inherits ObservableObject from CommunityToolkit.Mvvm
       - Dependencies injected: ICredentialService, INavigationService
       - [ObservableProperty] bool IsLoading (shows loading state during WebView2 init)
       - [ObservableProperty] string? ErrorMessage (shows errors)
       - InitializeWebViewAsync(WebView2 webView) method:
         a. Set UDF path to %LOCALAPPDATA%\CCInfoWindows\WebView2
         b. Create CoreWebView2Environment with explicit UDF path
         c. Call EnsureCoreWebView2Async with environment
         d. On failure: delete UDF directory, retry once (corrupted UDF recovery from 01-RESEARCH.md Pitfall 1)
         e. Set 30-second timeout using CancellationTokenSource
         f. Navigate to https://claude.ai/login
       - HandleNavigationCompleted(WebView2 sender, CoreWebView2NavigationCompletedEventArgs args) method:
         a. Call CookieManager.GetCookiesAsync("https://claude.ai")
         b. CRITICAL: Access cookie .Name and .Value ONLY on UI thread (threading constraint from 01-RESEARCH.md Pitfall 2)
         c. Find cookie with Name == "sessionKey"
         d. If found: save via CredentialService.SaveSessionToken, send AuthStateChangedMessage(true) via WeakReferenceMessenger, navigate to MainView
         e. If not found: do nothing (user is still in login flow)

    2. Create Views/LoginView.xaml:
       - Single WebView2 control filling entire page (HorizontalAlignment="Stretch", VerticalAlignment="Stretch")
       - No chrome, no app UI elements -- WebView2 IS the login page per locked decision
       - ProgressRing overlay for loading state bound to IsLoading
       - InfoBar for error messages bound to ErrorMessage

    3. Create Views/LoginView.xaml.cs (code-behind, minimal):
       - Resolve LoginViewModel from DI in constructor
       - Set DataContext
       - In Loaded event: call ViewModel.InitializeWebViewAsync(LoginWebView)
       - Wire WebView2.NavigationCompleted to ViewModel.HandleNavigationCompleted
       - NOTE: Code-behind is acceptable here because WebView2 requires direct control reference. The logic lives in the ViewModel.

    IMPORTANT constraints:
    - Network communication only to claude.ai (SECU-04) -- WebView2 naturally limits to whatever claude.ai loads
    - No special 2FA/Captcha handling -- WebView2 handles it natively per locked decision
    - WebView2 UDF explicitly at %LOCALAPPDATA%\CCInfoWindows\WebView2 per locked decision (SECU-05)
  </action>

  </done>
